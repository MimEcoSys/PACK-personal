# PD.METHOD.071 — Составление списка рабочих продуктов

> Код в каталоге методов стиля жизни и работы эпохи ИИ: **LMS.M.037** «Составление списка рабочих продуктов» (тождество). Метод — один из двух подметодов сводного метода LMS.M.010 ([PD.METHOD.072](PD.METHOD.072-work-product-per-task.md)). Разрез каталога (такт, необходимость, граф зависимостей) хранится в каталоге и графе РП-600, не в этой карточке.

## Определение

Составление списка рабочих продуктов — метод ведения одного общего списка ожидаемых результатов человека ([PD.WP.021](../04-work-products/PD.WP.021-work-product-list.md)). Каждую формулировку, полученную формированием рабочего продукта ([PD.METHOD.070](PD.METHOD.070-work-product-formulation.md)), человек сразу заносит в список строкой или обновляет ею уже существующую строку; на обзоре дня или недели список сверяется, и у каждой строки остаётся явный статус.

Строка списка описывает **намеченный** результат: её наличие не означает, что продукт уже существует или что работа сделана. «Активная» строка — строка о результате, который намечен или делается и по которому ещё не принято решение.

## Назначение

Результаты, названные у отдельных задач, без общего списка теряются: часть из них молча переходит изо дня в день, часть бросается без следа. Метод держит все намеченные результаты в одном месте и требует решения по каждому при сверке: бесконечный молчаливый перенос скрывает несделанный выбор.

## Состав метода

| Этап | Что происходит | Признак, что этап пройден |
|---|---|---|
| Занести строку | Сразу после формирования рабочего продукта формулировка (вид результата, предмет, роль, признак готовности) заносится в список; если результат уже есть в списке — строка обновляется, а не дублируется. | В списке есть строка с этой формулировкой и статусом «в работе». |
| Сверить список | На обзоре дня или недели проверяется каждая активная строка по её признаку готовности. | У каждой активной строки проставлен один из статусов ниже с датой сверки. |

**Статусы строки** — утверждения разного рода, они не сливаются в одно «закрыто»:

| Статус | Что утверждается |
|---|---|
| В работе | Результат намечен или делается, решения по нему нет |
| Готово по признаку | Признак готовности выполнен; записаны дата и признак, по которому проверено (поздняя правка признака эту отметку не переписывает) |
| Пауза с условием возврата | Работа отложена; записано, при каком условии она возобновится |
| Остановлено с причиной | От результата отказались; записаны причина и то, что из сделанного осталось полезным |

Если при сверке нет данных, достигнут ли результат, строка остаётся «в работе» с пометкой «нет данных» — отсутствие данных не равно «не сделано».

## Когда применять

- Сформулирован ожидаемый результат новой задачи (занесение строки).
- Обзор дня или недели (сверка списка).

## Когда не применять

- Нужно выбрать приоритетные проекты или расписать задачи по проектам — это стратегирование и список задач ([PD.WP.015](../04-work-products/PD.WP.015-task-list.md)): там единица — задача, здесь — ожидаемый результат.
- Нужно разместить работы во времени — это планирование ([PD.METHOD.009](PD.METHOD.009-planning.md)).
- Нужно закрыть проект целиком с итоговым документом — это закрытие проекта (LMS.M.038).

## Входы

| Вход | Описание | Обязателен? |
|---|---|---|
| Формулировка ожидаемого результата | Выход [PD.METHOD.070](PD.METHOD.070-work-product-formulation.md) | Да (для занесения) |
| Список рабочих продуктов | Текущая версия [PD.WP.021](../04-work-products/PD.WP.021-work-product-list.md) | Да |
| Обзор дня или недели | Место, где проходит сверка (например, закрытие дня, [PD.METHOD.012](PD.METHOD.012-day-rhythm.md)) | Да (для сверки) |

## Результат и как проверить

| Выход | Описание |
|---|---|
| Обновлённый список рабочих продуктов | [PD.WP.021](../04-work-products/PD.WP.021-work-product-list.md): каждая сверка, изменившая список, даёт его новую версию |

**Проверка результата:** у каждой формулировки, полученной за день, есть строка в списке; после сверки у каждой активной строки — статус с датой; ни одна строка не исчезла без статуса «готово по признаку», «пауза с условием возврата» или «остановлено с причиной».

## Ключевые различения

- [D.005](../01-domain-contract/01B-distinctions.md) Рабочий продукт ≠ описание — строка описывает намеченный результат; сам результат существует отдельно от строки.
- [D.038](../01-domain-contract/01B-distinctions.md) Задача ≠ формулировка работы ≠ работа — список держит ожидаемые результаты, а не задачи и не выполненную работу.
- Список задач ([PD.WP.015](../04-work-products/PD.WP.015-task-list.md)) ≠ список рабочих продуктов ([PD.WP.021](../04-work-products/PD.WP.021-work-product-list.md)) — разные единицы учёта; несколько задач могут работать на одну строку.
- Внесение в список ≠ обязательство: строка фиксирует намерение, а не обещание кому-то.

## Силы

| Сила | Напряжение |
|---|---|
| Один список ↔ много мест | Один список дешевле сверять; цена — его нужно держать доступным там, где появляются задачи. |
| Явное решение ↔ лёгкость | Статус «остановлено с причиной» требует признать отказ; без этого список растёт хвостом брошенных строк. |

## Искажения

| Искажение | Направление |
|---|---|
| Молчаливый перенос | Строка переходит со сверки на сверку без решения — выбор не сделан, но выглядит сделанным. |
| Готово = закрыто | Отметка «готово по признаку» принимается за закрытие задачи или за чужую приёмку. |
| Список задним числом | Строки заносятся вечером, после работы; список полный, но формулировки до работы не было. *Предположение составителя карточки; на применениях не проверено.* |

## Типичные сбои

- [PD.FAIL.006](../05-failure-modes/PD.FAIL.006-work-product-is-description.md) Рабочий продукт подменён описанием: строка списка принимается за сам продукт.

## Опора на свод принципов

Сверка 27.11.2026 (FPF Library, коммит 9d38fbf; РП-600 Ф25, пир-сессия 2026-11-27-15; чтение полного текста независимым проверяющим). Прямого паттерна о ведении личного списка ожидаемых результатов в своде нет; опора собрана из нескольких паттернов, часть — по аналогии.

| Паттерн | Что опирает | Граница |
|---|---|---|
| GOALS.4:4.3, :4.4, :4.1 | Запрет бросать молча: бесконечный молчаливый перенос скрывает несделанный выбор; исходы — продолжить, сменить средства, пауза с условием возврата, закончить; «достигнуто» — только когда результат выполнил свой признак; сверку назначать тогда, когда она ещё может изменить работу | Написано о целях, не о продуктах — перенос по аналогии |
| OPS.4:4.1, :4.2 | Учёт, сверяемый по расписанию; прогноз, план, наблюдение и решение — разные утверждения; периодичность и срок годности записей | Написано для нескольких участников; перенос на одного человека — адаптация |
| OPS.5:4.3, :4.5 | У каждой строки явное решение с причиной; отложенное остаётся видимым | Ограничения числа начатого метод не заявляет: для него паттерн требует единицы, интервала и правила счёта |
| OPS.7:4.1, :4.5 | Прежнее намерение остаётся видимым, пока явно не заменено; внесение в список не создаёт обязательства | Написано про обязательства между сторонами |
| OPS.Reference:3, :4 | Список — запись с ограниченным назначением; единица учёта (ожидаемый результат) отличается от задачи и требует правила идентичности | — |
| A.15.PROD:4.5; A.15.2:7b | Строка описывает намеченный результат, которого ещё нет | — |
| A.15.2:4.5 | При сверке «нет данных» — не отрицательный ответ | Написано о плане; для списка — аналогия |
| C.2.1:4.5 | Каждая сверка, изменившая содержание списка, даёт новую версию | — |

Отсеяны по тексту: MNT.2:9 (отставание обслуживания оборудования), SYSE.22 (пары «проблема — вариант решения» в инженерии), GOALS.7 (постановка задачи ИИ-агенту).

## Статус

**Статус:** `hypothesis`.

**Основание:** практика пилота (каталог РП-600; источник строки — практика пилота и 14 элементов культуры работы IWE); сверка со сводом FPF 27.11.2026. Статус `hypothesis` означает, что сравнения на применениях других людей нет, а не что практика не сложилась.

**Критерий пересмотра:** появятся данные, что явные статусы при сверке не уменьшают число молча брошенных результатов по сравнению с простым списком без статусов, или что один общий список систематически не поддерживается и распадается на несколько.
