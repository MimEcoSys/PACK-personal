# [PD.WP.021] Список рабочих продуктов

---

## Definition

**Список рабочих продуктов** — один общий записанный список ожидаемых результатов человека. Каждая строка — формулировка одного ожидаемого результата: вид (новый продукт, изменение существующего, удержание условия в пределах), предмет, роль, признак готовности, дата занесения и статус (в работе / готово по признаку / пауза с условием возврата / остановлено с причиной) с датой последней сверки.

Строка описывает **намеченный** результат: её наличие не означает, что продукт уже существует. Список ведётся постоянно, и каждая сверка, изменившая его содержание, даёт новую версию.

По роду список — документ, несущий описание намеченных результатов; рабочим продуктом в этом паке он назван по той же договорённости, что список задач ([PD.WP.015](PD.WP.015-task-list.md)) и бюджет времени ([PD.WP.001](PD.WP.001-time-budget.md)): записанный документ, который можно предъявить и проверить.

Список рабочих продуктов — это НЕ:
- Список задач ([PD.WP.015](PD.WP.015-task-list.md)): там единица — задача внутри приоритетного проекта, здесь — ожидаемый результат; несколько задач могут работать на одну строку.
- План: у строки нет срока, метода и места во времени.
- Отчёт о сделанном: статус «готово по признаку» говорит о состоянии результата, а не о том, как шла работа.

## Existence Criteria

| Criterion | Test |
|-----------|------|
| **Записан и один** | Список существует в одном месте, его можно открыть; параллельных списков того же назначения нет |
| **Полная строка** | У каждой строки названы вид результата, предмет, роль, признак готовности и дата занесения |
| **Явный статус** | У каждой строки один из четырёх статусов; у «готово» — дата и признак, по которому проверено; у «паузы» — условие возврата; у «остановлено» — причина |
| **Сверяется** | Есть дата последней сверки; сверка проходит на обзоре дня или недели |

**Existence check**: может ли другой человек прочитать список и понять, какие результаты намечены, какие готовы и по какому признаку, какие отложены до какого условия и от каких отказались и почему?

## Quality Criteria

| Criterion | Description | How to Verify |
|-----------|-------------|---------------|
| **Без молчаливого переноса** | Ни одна строка не переходит сверку за сверкой без решения | Сравнить две соседние версии |
| **Без исчезновений** | Строка не пропадает из списка без статуса | Сравнить две соседние версии |
| **Своевременность** | Строки занесены в момент обращения к задаче, а не задним числом | Дата занесения строки не позже начала работы над задачей |
